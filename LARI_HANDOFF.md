## Что это

**LARI.js — from kampung to KL**: 3D-платформер в стиле Mario (2.5D: 3D-графика, движение вбок), где **изучение JavaScript буквально открывает способности**. Персонаж бежит из ночной малайзийской деревни через тропический лес и вулкан в город Куала-Лумпур. *Lari* по-малайски значит «беги».

**Зачем:** проект для интервью на стажировку в **Rizurf Technology** (KL; их продукт — homefinderpro.ai, аренда жилья для экспатов в Bangsar South, KL Sentral, KLCC, Mont Kiara; фишки — Home Guide, Home Link, депозит 1,5 месяца). Интервью было запланировано примерно через неделю после 2026-10-01. В игре брендинг Rizurf **не используется** (только финальный текст «with your team»).

## Технологии

- **Three.js 0.169** через import map (CDN jsDelivr), ES-модули, **без сборки**.
- **Blender + Python (bpy)** — все 3D-модели генерируются скриптами и экспортируются в `.glb`.
- **Web Audio API** — 4 саундтрека и ~20 эффектов синтезируются в браузере, без файлов.
- Сохранение в `localStorage` (ключ `lari-js-save-v1`).
- Шрифты: Lilita One (заголовки), Rubik (интерфейс), JetBrains Mono (код). Стиль UI — «kopitiam-arcade»: кремовые карточки, толстые чернильные рамки, жёсткие тени, кнопки «нажимаются».

## Команды

```bash
# пересобрать модели (≈20–60 с каждая; "render" — ещё и PNG-превью в renders/)
blender -b --python blender/characters.py -- render
blender -b --python blender/world.py -- render
blender -b --python blender/enemies.py -- render

node tools/reach.mjs           # дальность прыжков
node tools/check_levels.mjs    # ОБЯЗАТЕЛЬНО после любых правок уровней/физики (≈15 с, должно быть "ALL LEVELS OK")
node tools/dump_level.mjs 0 1 60 80
```

## Геймплей

### Уровни (генерируются из чанков, детерминированно по seed и сложности)
| # | Уровень | Длина | Ворота (тема) | Сила |
|---|---|---|---|---|
| 1 | Night Kampung | ~1150 клеток | `let` → **`for` (сила)** → `if/else` | Двойной прыжок |
| 2 | Rainforest | ~1250 | arrays → **`function` (сила)** → objects | Рывок |
| 3 | Volcano | ~1350 | events → **`async/await` (сила)** → `try/catch` | Парение |
| — | Kuala Lumpur | финал | — | экран с городом и письмом от Артемия |

- На каждом уровне 3 код-ворот (≈20%, 45%, 75%). Ворота — световой барьер **до неба** (не перепрыгнуть). Квиз: короткий урок + вопрос. Ответ на ворота силы даёт способность; за ворота-урок +10 монет. Пройденные темы сохраняются; при повторе ворота открываются сами.
- Сразу после ворот силы стоит «доказательство»: стена в 3 клетки / пропасть 10 / лавовое поле 15 — **без новой силы непроходимо** (это проверяет валидатор).
- **Чанки:** run (с рядами кубов и `{ }`-блоками), gap, step, pyramid (кубы), bridge (парящие кубы над пропастью/лавой), climb (подъём по уступам), spikes, spring, descend, special (сцена с врагами темы).
- Клетки (`T` в physics.js): GROUND, PLATFORM, BLOCK (`{ }`), USED, HAZARD (лава — смерть), BARRIER (ворота), BRICK (куб), SPIKE (шипы — урон, не смерть).

### Враги по уровням
- Деревня: **bug** (божья коровка), **ayam** (курица, замечает и бросается), **bat** (летучая мышь, пикирует).
- Лес: **beetle** (зелёный жук), **spider** (спускается на нити), **siput** (улитка: прыжок → панцирь, пнуть — скользит и сносит врагов), **fly** (оса).
- Вулкан: **blob** (лавовый сгусток из лавы, не топчется), **crab** (магмовый краб с шипами — сверху нельзя, рывок разбивает), **firebat**.
- Рывок убивает большинство врагов. У каждого врага `min` — с какой сложности он появляется.

### Физика (js/physics.js, всё проверено `tools/reach.mjs`)
- Прыжок: ~2,2 вверх / ~5,2 вперёд (тап: 1,9 / 4,5). Двойной: ~4,3 / 8,5 (тап: 3,6 / 7,8). Рывок: ~12. Парение: ~22.
- `minJumpTime 0.16` — даже короткий тап даёт нормальный прыжок (иначе на телефоне не работал двойной).
- Прыжок с земли и двойной прыжок **никогда не уменьшают** скорость взлёта (пружины/отскоки). Пружина срабатывает и при наступании.
- Шипы: «прощающий» хитбокс (только ноги, не по краю).
- Уровни строятся с запасом под **тап-прыжки**: одиночный ≤4 пропасть/≤1 подъём; двойной ≤6/≤3; рывок ≤9; парение ≤14.

### Сложности (`DIFFICULTY` в save.js + `DIFF` в levels.js)
| | Пропасти | Враги | Чекпоинты | Ворота | Монеты |
|---|---|---|---|---|---|
| Easy | уже | ×0,55 | часто | 3 варианта | ×1 |
| Normal | — | ×1 | ~85 клеток | 4 варианта | ×1,5 |
| Hard | полные | ×1,5 | ~110 | таймер 30 с, ошибка = −жизнь | ×2 |
| Very hard | полные | ×2,1 | ~160 | таймер 15 с, ошибка = −жизнь | ×3 |
3 жизни всегда (+1 с предметом). Падение/лава — минус жизнь и чекпоинт; враг/шипы — минус жизнь с отбросом.

### Магазин «Kedai» (save.js → `SHOP`)

- Шапки: Snapback 60, Party 60, **Songkok** 90, Headphones 120, Crown 400.

### Управление
- Клавиатура: ← → / A D, прыжок Space/↑/W/Z, рывок Shift/X/J **или двойное нажатие ← / →**, пауза Esc/P, ответы в квизе 1–4.
- Телефон: ◀ ▶ и ▲ (зелёной кнопки рывка **нет** — по просьбе; рывок двойным тапом по ◀/▶). Захват указателя, блокировка зума iOS (двойной тап и щипок).

## Технические решения, которые важно не сломать

- **Имена частей моделей:** Blender переименовывает дубли в `Head.001` → в glTF `Head001`, а GLTFLoader добавляет `_1`. Искать части только через `byName(root, 'Head')` из `assets.js`.
- **Instancing по чанкам** (`instance()` в assets.js, 48 колонок на чанк, `computeBoundingSphere`) — тайлы, кубы, шипы, декор. Около 41 draw call на кадр.
- **Отсечение сущностей:** обновляются и рисуются только объекты в радиусе ~26 клеток от игрока (`tick()` в main.js). Использованные `{ }`-блоки помечаются `alive = false`, иначе всплывает старая модель.
- Физика — фиксированный шаг 1/120 с.
- Материалы с transmission в glTF переводятся в обычную прозрачность (дешевле на телефоне).

## Что проверено, а что нет

**Проверено:** валидатор — все 12 вариантов (3 уровня × 4 сложности) проходимы тапами, ворота силы не обходятся; в браузере — уровни без ошибок, квиз, ворота, двойной прыжок, магазин и примерка, сохранение, вид на 375 px.

**Не проверено:** полное прохождение живым человеком, реальный FPS на телефоне, звук на слух, финальный экран KL после настоящего прохождения.

## Критика и идеи на будущее (от самого разработчика)
1. **Самое важное для интервью:** уровни по ~10 минут — интервьюер поиграет 2–3 минуты. Нужен **Demo run** (≈3 минуты, по одним воротам каждого типа).
2. Однообразие чанков — добавить 3–4 «запоминающихся момента» на уровень (нашествие кур, паучий полог, поднимающаяся лава).
3. Враги атакуют без телеграфа — нужны предупреждения (замах курицы, тень паука, пузыри на лаве).
4. Мало «сочности»: тряска экрана, hit-stop, анимация смерти, затемнение при возрождении.
5. Hard/Very hard в основном «больше врагов» — добавить новые испытания.
6. Двойной тап для рывка может срабатывать случайно; возможно вернуть маленькую кнопку.
7. На высоких плато в кадре много «стены земли».
8. Первая загрузка ≈6 МБ.
9. Сильные стороны для рассказа на интервью: «концепция → способность», модели из кода, синтез звука, доказанная проходимость уровней.
